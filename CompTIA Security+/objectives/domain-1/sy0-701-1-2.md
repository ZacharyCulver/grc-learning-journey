# SY0-701 objective 1.2: Fundamental security concepts

[Security+ index](../../README.md) · Domain 1: General Security Concepts

These are original study notes aligned to the public CompTIA SY0-701 V7 exam objectives, not official CompTIA training or exam questions.

## Explain it

Confidentiality restricts disclosure; integrity protects accuracy and completeness; availability keeps services usable. Authentication verifies identity, authorization limits actions, and accounting records actions. Non-repudiation requires credible evidence of origin or action; a digital signature can help, whereas encryption alone mainly provides confidentiality. A gap analysis compares current controls with a defined target state.

Zero Trust removes implicit trust based on network location: evaluate identity, device and context, grant least-privilege access, and continually reassess. The **control plane** determines and administers policy; the **data plane** enforces access at the policy enforcement point. Physical measures include guards, badges, fencing, bollards, lighting, sensors, and access vestibules; choose for the actual risk. Deception tools such as honeypots, honeyfiles and honeytokens provide signals when touched, but should not be treated as a substitute for protecting real assets.

Keep the distinctions practical: a hash can detect modification but does not make a file secret; a backup improves recoverability but needs testing to support availability.

## Deeper distinctions

Integrity is not the same as authenticity. A hash comparison can reveal that bytes changed, but if an attacker can replace both file and published hash, it does not authenticate the publisher. A trusted digital signature adds an identity claim when the private key and certificate are trustworthy. Availability requires capacity, redundancy, recovery and protection from intentional denial; a replica can mirror corruption, so restoration still matters.

In Zero Trust, the policy engine decides, the policy administrator establishes or terminates the connection, and the enforcement point gates traffic. Continuous evaluation uses identity, device posture and context; “inside the network” is not authorization. A control plane describes decisions and configuration, while a data plane handles the actual application traffic. A honeypot is instrumented bait: isolate it, monitor interactions, and do not let it become a pivot.

**Decision drill:** An administrator authenticates using a smart card but is denied access to a database. Authentication succeeded; authorization failed. If the event was logged, accounting supplied evidence. Explain which CIA property the denial protects and what evidence would support an investigation.

## Additional blueprint concepts

Authentication applies to services and devices as well as people: a service certificate can help one system validate another. Authorization models determine what an authenticated subject may do. In Zero Trust, an enforcement point sits on the data path; the policy engine decides and the policy administrator helps establish or end access. A logical “trusted zone” should not be mistaken for blanket permission.

Physical sensors solve different problems. Infrared detects heat or beam interruption; pressure senses weight or contact; microwave and ultrasonic systems emit waves and detect changes in their reflections. Consider nuisance alarms, placement and environmental conditions. A honeytoken is a planted credential or data marker that should never be used legitimately; its use can signal access to a protected area.

## Apply it

An ISSO reviewing a system boundary finds shared admin accounts. Map the issue to accountability and non-repudiation, then propose unique identities, privileged access controls and log review.

## Active recall

Explain CIA and AAA without notes; distinguish the Zero Trust policy decision from the point that enforces it.
