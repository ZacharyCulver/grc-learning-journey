# SY0-701 objective 3.2: Securing enterprise infrastructure

[Security+ index](../../README.md) · Domain 3: Security Architecture

Original study notes aligned to the public CompTIA SY0-701 V7 blueprint; not official training or exam questions.

## Explain it

Place controls where traffic and trust boundaries actually exist. A screened subnet separates public-facing services from internal resources; segmentation may be physical or logical through VLANs, subnets and policy. Firewalls enforce permitted paths, IDS detects and IPS can block, and a load balancer distributes requests without necessarily being a security control. Choose secure access methods and protocols for administration, data transfer and remote connectivity.

Consider failure modes and operational tradeoffs: an inline control can stop malicious traffic but can also disrupt service if misconfigured. A VPN protects a connection but does not make a compromised endpoint trustworthy. Wireless deployments need secure authentication and encryption, site surveys, rogue-device detection and attention to coverage. Document data flows and rule owners; validate both allowed business traffic and blocked paths.

## Deeper distinctions

A secure network diagram should show zones, permitted flows, authentication points and inspection. Place public-facing services in a screened segment, protect the internal application/database tiers, and allow only required source-to-destination paths. Physical isolation separates hardware; logical segmentation depends on correct routing and policy. Zero Trust access can add identity and device-context checks even after a network path exists.

An IDS observes and alerts; an IPS can drop inline traffic and therefore needs careful failure-mode planning. A web application firewall interprets HTTP requests but does not replace secure code. NAC evaluates devices before network admission; VPN encrypts a tunnel, not the safety of either endpoint. Administrative access should use secure protocols, MFA and restricted management networks; disable unnecessary insecure services. Test denied as well as allowed traffic after rule changes.

**Design drill:** A vendor needs temporary access to one maintenance service. Draw the path, authentication, allowed destination and time limit, then specify logs and a test proving they cannot reach adjacent systems.

## Additional blueprint concepts

Failure mode changes the security/availability tradeoff: **fail-open** permits traffic when a control fails, preserving access but potentially bypassing policy; **fail-closed** denies traffic, protecting the boundary but potentially stopping the mission. An inline IPS can block; a passive tap observes without interrupting the flow. An active device may transmit or enforce, while passive monitoring observes. Placement should reflect security zones and what each device can actually see.

A jump server concentrates controlled administrative access; a proxy intermediates requests; a WAF evaluates web traffic. Layer 4 filtering uses transport/port context, whereas Layer 7 controls interpret application traffic. A UTM bundles several capabilities; an NGFW can add application awareness; neither label proves the exact policy is enabled. Port security limits endpoint connection at a switch; 802.1X uses EAP to authenticate network access. For remote connectivity, distinguish TLS-protected sessions, IPsec tunnels, VPN access and SD-WAN path management. SASE combines network access with cloud-delivered security functions, but inspect its actual implementation and policy.

## Apply it

A public web service needs a database. Allow only the web tier's required connection to the database tier, block direct internet access to the database, log denials and verify rules with tests.

## Active recall

Sketch an internet-to-web-to-database flow and place a control at each trust boundary. How do IDS and IPS differ in consequence?
