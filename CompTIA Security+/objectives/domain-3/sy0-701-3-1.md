# SY0-701 objective 3.1: Architecture models and security implications

[Security+ index](../../README.md) · Domain 3: Security Architecture

Original study notes aligned to the public CompTIA SY0-701 V7 blueprint; not official training or exam questions.

## Explain it

Cloud, on-premises and hybrid designs shift which party operates and secures each layer; a shared-responsibility matrix makes those boundaries explicit. Virtualization, containers, serverless and microservices can improve deployment and isolation but add orchestration, identity, image and interface risks. Infrastructure as code makes changes reproducible yet can propagate an insecure template at scale. Software-defined networking centralizes policy but its controller becomes a critical dependency.

Compare centralized with decentralized control, scalability, availability, resilience, cost and recovery—not merely whether a technology is fashionable. IoT, embedded devices, industrial-control/SCADA systems and real-time systems may have long lifecycles, safety constraints and limited patch windows. Physical isolation or an air gap reduces some remote paths but does not eliminate removable-media or maintenance risk.

## Apply it

A plant controller cannot be patched during production. Segment it, restrict maintenance access, monitor protocol traffic, document recovery and coordinate changes with operations so safety and availability remain explicit.

## Active recall

For a cloud-hosted application, identify two customer-owned controls and two provider-owned controls; explain why a container is not a complete security boundary.
