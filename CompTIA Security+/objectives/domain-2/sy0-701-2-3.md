# SY0-701 objective 2.3: Vulnerability types

[Security+ index](../../README.md) · Domain 2: Threats, Vulnerabilities, and Mitigations

Original study notes aligned to the public CompTIA SY0-701 V7 blueprint; not official training or exam questions.

## Explain it

A vulnerability is a weakness that can be exploited in context. Application examples include injection, cross-site scripting, buffer/memory flaws, and race or time-of-check/time-of-use errors. SQL injection changes a database query's meaning; XSS runs untrusted script in a user's browser. Misconfiguration, weak cryptography, unpatched operating systems, unsupported legacy software, exposed cloud storage, mobile/virtualization flaws and supply-chain weaknesses may create comparable risk. A zero-day is a flaw with no available vendor fix at the time, not simply any severe vulnerability.

Distinguish vulnerability from exploit and impact: a bug is the weakness, exploit is the method, and loss of data or service is a consequence. Exposure, privileges, compensating controls and business criticality affect prioritization beyond a score.

## Deeper distinctions

Memory corruption can change control flow or expose data; a buffer overflow is one manifestation. A race condition arises when the result depends on timing, with TOCTOU occurring when a resource changes between validation and use. SQL injection executes unintended database commands because untrusted data is combined with query structure; parameterized queries separate data from code. XSS places executable content in a victim's browser; output encoding appropriate to context and safe templating are central defenses.

Cloud storage exposure may be a configuration or permission failure rather than a defect in cloud software. Virtual-machine escape crosses an isolation boundary; a malicious update or dependency is a supply-chain path. Weak crypto, old firmware, unsupported OSs, and default settings all widen exposure. A zero-day describes lack of an available fix at discovery/exploitation, not a severity score.

**Decision drill:** A scanner reports a vulnerability on a host with no route from the internet. Verify the finding, its reachable path, compensating controls and asset importance before ordering work. “Not internet-facing” does not mean harmless to an insider.

## Additional blueprint concepts

Firmware and end-of-life hardware can remain vulnerable even if the operating system is patched. In virtualization, escape means crossing from a guest into a host or another isolation boundary; resource reuse can expose residual data if storage or memory is not cleared. Mobile sideloading bypasses the usual application distribution path, and jailbreaking/rooting removes platform restrictions; neither automatically proves compromise but both change the risk profile.

A malicious software update can be signed yet harmful if the build or signing process was compromised. Treat cloud provider, hardware and software dependencies as distinct supply-chain paths; ask where an update originates and who can alter it.

## Apply it

A public application interpolates user input into SQL. Use parameterized queries and validate input; assess whether credentials and database permissions limit the blast radius.

## Active recall

Contrast SQL injection and XSS. Why can an old, unsupported system remain high risk even when no new CVE is announced?
